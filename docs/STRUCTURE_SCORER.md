# 结构打分方案设计（STRUCTURE_SCORER.md）

> 状态：Phase A 已实现（影子模式）。本文档记录设计决策，供后续迭代参考。

## 问题

文生图动漫图最常见的废因是**人体结构崩坏**（多指/并指/反关节/多肢），而现有的
质检（模糊/纯色）与美观度模型都抓不住它。需要一个专门的"结构合理性"打分器。

## 关键认知（为什么不能直接用 YOLO 置信度当畸形分）

1. **YOLO 置信度 ≠ 质量**。ADetailer 的工作方式就是"检出（不管好坏）→ 重绘"，
   畸形的手照样被高置信度检出。置信度主要反映**可见性 + 风格域差距**。
2. **检不出 ≠ 有问题**。手放背后、被遮挡、出画，都检测不到手——这是 N/A，
   不是低分。把"未检出"当扣分项会系统性误伤正常构图。
3. **真正的质量信号在几何**：手指数量异常在关键点模型上表现为指尖聚集/指节比例
   错乱；肢体异常表现为左右不对称、关节融合、角度反折。

## 总体设计：两级"清单 + 条件评估"

```
Stage 1 清单  : 画面里有哪些部位？        （DWPose 关键点置信度 + YOLO 检出）
Stage 2 条件  : 只对"在"的部位做几何检查  （规则引擎）
检不出 → N/A（不扣分不加分），综合时只在可用部分间归一化
```

## 模型选型

| 模型 | 角色 | 依赖 | 大小 |
|---|---|---|---|
| **DWPose (yzd-v)** YOLOX-L + DW-LL | 主力：133 关键点（身体17+脚6+脸68+双手42） | onnxruntime（无 torch） | ~340MB |
| **YOLO 板块**（0–4 个模型，用户配置） | 辅助可见性 + 部位置信度 | ultralytics（含 torch） | 每个 ~6MB |

- DWPose 推理为**纯 numpy + PIL 实现**（`scorers/dwpose_infer.py`），复刻
  mmpose top-down 流程：letterbox 640 → YOLOX 人体框（NMS）→ 每人裁 288×384 →
  SimCC 解码 133 点。SimCC 输出自动检测 logits/概率（>1.2 视为 logits 过 sigmoid）。
- 模型下载走 hf-mirror 优先 + 断点续传（复用 aesthetic_backends 的多源下载器）。

## 三个子分（parts）

### 1. body（骨架，权重 0.35）

人体检出后基于 COCO17 的规则（v1，保守阈值，动漫比例差异大所以只抓极端）：

| 规则 | 阈值 | 扣分 |
|---|---|---|
| 双肩融合（多肢征兆） | 肩距 < 0.15×躯干 | -0.40 |
| 双腕融合 | 腕距 < 0.06×躯干 | -0.30 |
| 左右臂/腿长不对称 | 长度比 > 1.35 | -0.25 |
| 单侧关节融合（肩肘/髋膝零距离） | < 0.05×躯干 | -0.20 |
| 颈部比例异常 | 颈/肩宽 > 1.6 | -0.15 |
| 骨架整体低置信 | body_conf_mean < 0.25 | flag only |

### 2. hands（手部，权重 0.35）——核心

可见性门控：`hand 21 点平均置信度 ≥ hand_vis(0.40)` 且 `掌长 ≥ 0.05×人物框高`，
否则 N/A。可见的手按 21 关键点几何检查（v1）：

| 规则 | 原理 | 扣分 |
|---|---|---|
| 指尖顺序异常（小指>中指） | 正常手中指离腕最远；固定拓扑模型在多指/错位时会给出异常排序 | -0.30 |
| 指节比例异常 ≥2 根 | 远节 > 1.6×近节 为生理不可能 | -0.25×n |
| 指尖聚集 | 两指尖距离 < 0.10×掌长（并指/融合指签名） | -0.25×n |
| 关节极端反折 | PIP 角 < 30° | -0.25 |

多只手取**均值**；多个人体取**最差人**（body）与全部手均值（hands）。

### 3. yolo 板块（权重 0.30，用户要求：整体板块，分平均分配）

- 配置 `structure.yolo.models`（**上限 4 个**，硬截断）；
- 每个模型独立跑，`source` 支持本地路径或 `"repo_id:filename"`（自动下载）；
- 单模型分 = **top-k(4) 高置信检出中的最低置信度**（该部位最差可见实例的质量代理）；
- 无任何 ≥ vis_floor(0.35) 的检出 → 该模型 N/A，**不参与板块平均**；
- 板块分 = 各可用模型分的简单平均。

> 为什么用 min-of-top-k 而不是 max：一张图两只手都畸形时，max 会被好的一只掩盖；
> min 反映"最差可见实例"。但注意这只是代理信号——真正的手指质量判断仍以
> DWPose 几何为主。置信度在动漫图上普遍偏低，阈值需要靠影子模式数据校准。

## 汇总与影子模式

```
structure = Σ(w_part × score_part) / Σ(w_part)   （仅可用部分）
全部 N/A  → score() 返回 None → pipeline 跳过 → 综合分在剩余打分器间归一化
```

**影子模式（shadow: true，默认）**：pipeline 计算并保存 structure 结果（UI 展示 +
feedback 记录），但**不计入 composite**。原因：v1 阈值全是拍的，直接参与排序会
误伤；先用真实数据校准（见 docs/FEEDBACK_FORMAT.md 的分析建议），再转正。

转正时：`config/curator.yaml` 中 `structure.shadow: false` 且
`weights.structure: 0.2`（起步），相应下调 quality（如 0.6/0.2/0.2）。

## UI 呈现

- 卡片：紫色虚线 `结构 NN` chip（标注影子模式）+ 部位可见性图标（人✓ 手L✓ 手R— …）；
- flags 混入现有红色 flag 区；
- Lightbox：`☸ 骨架 (O)` 按钮 / O 键 → 叠加渲染骨架+手部关键点（/api/overlay，带缓存）；
- 头部筛选：`只看有结构问题的组`。

## 数据闭环（Phase C 的基础）

每次勾选「记录本次导出」的导出 = 一条完整会话快照（全部组、全部图、全部分数、
全部几何特征、用户最终选择），JSONL 追加写入 `data/feedback/`。格式规格：
**docs/FEEDBACK_FORMAT.md**（分析规则、样本定义、退出影子模式的统计标准都在那里）。

用户的每次"选中/换选/全部不选"就是免费标注。积累 ≥300 配对样本后：
1. 按 FEEDBACK_FORMAT.md §分析建议 校准阈值；
2. 或直接以 feats 特征行训练小分类器替代手工规则。

## 已知局限（诚实清单）

- **脚/脚趾**：DWPose 脚部只有 6 点（大脚趾/小脚趾/脚跟 ×2），无法做趾级几何检查。
  脚趾畸形主要靠 YOLO 板块（如配置 foot 模型）+ 美观度模型兜底。
- **动漫域差距**：DWPose 在真人照片上训练，动漫手（简化线条、非常规视角）的
  关键点置信度整体偏低——这正是 hand_vis 门控 + 影子模式存在的原因。
- **侧身/背面构图**：单侧肢体 N/A 是设计行为，不视为缺陷。
- **多人物图**：max_persons=3 限制，规则按人分别跑；body 取最差。
- **YOLO min-of-top-k 是弱信号**：置信度对"畸形但画得完整"的手不敏感；期待
  Phase C 用反馈数据学习替代。

## 性能

- GPU：~0.15–0.4s/图（det+pose）；CPU：~1–3s/图。
- 每张图独立推理，无跨图缓存（同图 overlay 有 PNG 缓存）。
- 扫描 1000 张 CPU 预计 30–50 分钟——建议 GPU 或先小批量试用。
